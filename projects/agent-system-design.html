Agent 应用开放平台

我的职责

我定义规划、执行、记忆、检索和评估五层的输入输出，设计工具注册、异常重试、会话记忆和知识检索的规则。

业务团队需要在一个工作台接入知识和工具、搭建与调试 Agent，并把做过的配置复用到新任务。

做到哪一步

平台方案与配置界面

完成五层平台方案、编辑配置及编排界面，并整理可复用的 Agent 能力清单。

关键决策

把计划和执行拆成不同步骤

规划层输出任务和结构化参数，执行层调工具并回传结果，评估层沿任务轨迹记录输出，方便调试时定位是哪一步出错。

工具接入时约定参数和异常处理

定义注册参数、调用约束、错误类型和重试机制。工具异常后按类型决定继续、重试或停止。

分别管理会话状态和外部知识

短期上下文支持当前对话，长期记忆保留可复用状态，RAG 按任务检索外部资料。分别管理三种信息，便于追溯回答依据。

方案与验证

平台上的四类真实任务

企业知识问答要带引用。业务自动化要能完成查询、计算和写入。复杂内容生产需要大纲、素材、生成、核验和导出分工。客服要在多轮对话里维持长期偏好和当前任务目标。

我设计任务澄清、规划、工具执行、知识检索和结果评估的分工。业务人员在配置页选择模型、知识和工具，在编排页构建单 Agent 或多 Agent 流程，并可在发布前调试。

工具、记忆和检索规则

工具以稳定的 JSON Schema 声明必填、枚举、默认和边界，统一回传状态、数据及错误。定义权限、超时、重试和幂等键，保留工具结果供下一步调用，高风险动作由人工确认。

短期记忆用滑动窗口与摘要保留事实和下一步，长期记忆按用户及组织记录稳定偏好并支持过期更新。RAG 采用语义切分、向量召回与重排，有证据才引用，空结果转澄清或人工。

调试与评估

用澄清、执行、确认、收口四个状态显式记录步骤，中断后可从最近的稳定状态恢复。工具异常可转为咨询或转人工，保留会话上下文。

按企业策略设计 GPT、Moonshot、DeepSeek、文心、GLM 和通义等模型的路由。方案用离线样本和在线埋点跟踪任务完成、工具调用成功、引用准确、采纳与重试。

原案例资料 · Agent 应用开放平台

项目背景与范围

项目概述

  • 基于「明月 AI 开放平台」（moonai.bot）：把数据、提示工程、向量知识库、工作流与多模型调用等企业落地 LLM 所需的复杂组件产品化；在统一工作台中完成系统提示词、Few-shot、变量、知识库（RAG）、用户持久记忆与插件（Function Call）等配置与运行保存，支撑标讯、写作、招聘、会议、合同、发票等多条业务线 Agent 快速复制上线。

业务场景

  • 面向企业多场景的 LLM 应用搭建与治理平台，覆盖 Agent 配置、RAG、Workflow、工具调用、调试发布与资产复用

背景

  • 企业自建大模型应用往往重复造轮子；单体提示词方案在复杂任务中又容易失控：工具调用不稳定、上下文丢失、引用不可靠、会话越长越偏航。

目标用户

  • AI产品经理、应用工程师、算法工程师、平台架构师

项目目标

  • 建设可复用的 Agent 应用开放平台，让业务方在统一界面内完成配置、调试与发布，并形成可治理的 Agent 资产。

用户痛点

  • 工具调用参数经常不合法，导致函数执行失败率高。
  • 会话上下文过长后失焦，关键事实被覆盖或遗忘。
  • RAG召回结果质量不稳定，回答出现幻觉或引用不准。
  • 多轮对话缺少状态机，无法区分澄清、执行、确认、收口阶段。

使用场景

  • 企业知识问答：在文档库中检索证据并输出带引用的回答。
  • 业务流程自动化：根据用户目标调用多工具完成查询、计算、写入。
  • 复杂内容生产：多Agent分工完成大纲、素材、生成、校验、导出。
  • 客服和运营场景：保持长期用户偏好并在多轮中持续对齐目标。
产品方案与系统设计

产品方案

  • 采用“规划Agent + 执行Agent + 记忆层 + 检索层 + 评估层”的五层架构，把每次交互从自由生成变为有约束的任务执行。

为什么用 AI

  • 当任务涉及多步骤决策、外部系统调用、知识检索和持续对话时，需要 Agent + Workflow 才能稳定交付。

AI 的作用

  • 在开放平台内完成 Agent 的可视化搭建、调试与发布，把工程能力产品化

功能模块

  • Agent路由中心：按任务类型选择单Agent或多Agent协同执行。
  • 工具注册中心：标准化工具Schema、权限与超时策略。
  • 记忆管理器：会话摘要、用户画像、组织知识三层记忆存储。
  • RAG服务层：索引构建、召回重排、引用注入与答案约束。
  • 对话状态机：澄清-执行-确认-收口四阶段可观测流转。

系统架构

  • 交互层：负责输入解析、意图识别、澄清追问和响应组装。
  • 规划层：将用户目标拆解为可执行步骤，决定是否调用工具与检索。
  • 执行层：统一Function Call协议，处理参数校验、重试与回写。
  • 知识与记忆层：短期记忆维护会话状态，长期记忆维护用户画像与偏好。
  • 观测与评估层：记录调用日志、命中率、成功率、用户采纳率。

AI 与产品分工

  • AI：任务理解、步骤规划、检索增强生成、答案整合
  • 规则：参数校验、权限控制、状态流转、失败重试
  • 人工：确认高风险操作、审核关键结果、更新知识策略
  • 兜底：工具失败降级到纯问答或转人工并保留上下文

Agent 分工

  • Planner Agent：将目标拆分为子任务并分配到工具或子Agent。
  • Executor Agent：按计划逐步执行Function Call并回传结构化结果。
  • Memory Agent：维护会话摘要与用户长期偏好，控制上下文预算。
  • Retrieval Agent：结合检索与重排提供高相关证据片段。

技术方案

  • 私有化部署与多模型路由：支持 GPT-4/4V/4o/4o mini、Moonshot、DeepSeek、文心一言 4.0、GLM-4、通义千问 Max 等（按企业策略选型）。
  • Function Calling：以JSON Schema约束参数，配合工具返回结构化结果。
  • 向量检索：文档切片、Embedding、重排和引用注入提高回答可信度。
  • 会话状态管理：短期窗口 + 摘要压缩控制上下文长度和稳定性。
  • 长期记忆存储：保存用户偏好、历史任务与组织知识索引。
  • 评估系统：离线样本评测 + 在线埋点监控持续优化Agent质量。

Agent 设计方法

  • 设计方法
  • 先定义任务成功标准，再拆成可验证的子任务。
  • 每个子任务都定义输入、输出、错误码和超时策略。
  • 复杂任务优先采用“规划-执行-校验”三段式编排。
  • 高风险操作加人工确认节点，避免全自动误操作。
  • 工具调用
  • 工具接口必须有稳定Schema（必填项、枚举、默认值、边界校验）。
  • 工具返回统一结构：status、data、error_code、error_message。
  • 设置重试和幂等键，防止重复执行导致脏数据。
  • 工具结果回写会话上下文，供下一步Agent继续推理。
  • 短期记忆
  • 会话内保留关键事实、决策理由、任务约束和后续动作。
  • 采用窗口 + 摘要压缩，避免上下文爆炸和成本失控。
  • 将“临时事实”和“用户偏好”分离，防止污染长期记忆。
  • 长期记忆
  • 长期记忆按 user_id / org_id 命名空间存储，支持跨会话复用。
  • 仅沉淀稳定偏好和高价值知识，避免把噪声写入长期层。
  • 提供更新与过期机制，确保记忆可追踪、可纠错。
  • 文档切片遵循语义完整原则，避免过碎或过长片段。
  • 召回后进行重排并限制上下文数量，优先高置信证据。
  • 回答必须包含引用来源，缺证据时触发澄清或拒答。
  • 索引更新策略与业务节奏同步，防止知识过期。
  • 把对话拆成澄清、执行、确认、收口四个状态。
  • 每轮都更新任务状态和下一步计划，避免对话漂移。
  • 在中断后可从最近稳定状态恢复，而不是整段重来。
  • 高风险场景必须二次确认并展示将执行的动作。

个人职责与复盘

职责概述

  • 平台侧能力规划、编排与配置体验设计、与业务侧 Agent 资产沉淀协同

个人工作

  • 定义Agent系统分层架构与各层输入输出协议。
  • 制定Function Call工具注册规范、异常分类和重试策略。
  • 设计短期/长期记忆协同机制与RAG召回策略。
  • 输出多轮对话状态机与评估指标体系，支持持续迭代。

复盘

  • Agent设计本质是系统设计，不是Prompt堆叠。
  • 越复杂的任务越要把“自由生成”改造成“受控执行”。
  • 记忆、工具、检索和状态机必须统一设计，才能真正稳定。

经验与后续考虑

  • 优秀的 Agent 产品不是“回答更聪明”，而是“执行更稳定、结果更可控、演进更可持续”。
