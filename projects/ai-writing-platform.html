AI 智能写作平台

我的职责

我负责工作台、研究报告、解决方案与素材库的信息架构，定义大纲、生成、确认、改写和资料引用的流程。

研究员和方案人员需要把资料、提纲与审阅意见合成稿件。生成长文时，要能校对章节，也要能只改其中一段。

做到哪一步

工作台与写作流程设计

完成工作台界面、写作状态和素材库方案，覆盖大纲确认、人工审阅、全文对比与 Word 导出。

关键决策

先确认三级大纲，再分章生成

报告和解决方案复用生成流程，各有入口和模板。用户先调整大纲，再按章节生成、检查并确认正文。

局部改写和全文优化各走一条路

局部改写从选区给出候选，全文优化用双屏对比。用户确认后才把改动写回工作区。

资料删除后，同步从检索中移除

定义素材上传、清洗、分块、向量化和召回流程。引用只使用有效素材，删除后同步清理检索索引。

方案与验证

写作发生在哪里

研究人员用 AI 生成、导入 PDF 或手工编排大纲，再对单章扩写、缩写、续写和总结。销售填写行业、岗位及痛点，得到四段式解决方案草稿。运营也可处理政策与竞对快讯、内部周报和对外宣传文案。

首页统一发起报告或方案，历史项目可以恢复。正文采用流式写作，局部修改可采纳、重试或弃用，全文优化时双屏比较，最后由业务人员确认并导出 Word。

素材怎样进入正文

通过 Function Call 接入搜索 API 与网页解析，将搜索、定位和内容抽取串起来。公共素材、项目素材和网页内容统一清洗、分块和向量化。界面让用户看到处理状态，删除也同步到索引。

用检索评估、证据标记和引用校验约束写作；大纲、章节写作、素材检索、摘要记忆和全文优化分工执行。章节摘要、用户记忆与滑动窗口让后续章节沿用关键事实，同时控制上下文长度。

如何判断交付能用

设计大纲最多三层、材料大小及提示长度限制、四段式输出和 Word 模板映射。解析失败、上下文超限和流式中断均能提示并恢复，业务人员核验事实、权限和引用后交付。

方案把首字小于 2 秒、连续测试结构遵循率 100% 设为目标，并跟踪生成成功率、推荐问题点击率、复制率和导出率。

项目全貌

原案例资料 · 智能写作平台

项目背景与范围

项目概述

  • 围绕“项目大纲-素材检索-生成写作-全局优化-导出”的完整链路，构建可复用的企业级 AI 写作工作流。

业务场景

  • 覆盖研究报告、解决方案、市场洞察与公众号素材库的协同写作流程，支持素材检索、分步生成、全文优化与导出复用

背景

  • 业务侧在报告与方案写作中存在资料分散、逻辑搭建慢、内容复用差和长文一致性弱的问题；市场洞察类工作还需高频阅读政策与竞对长文，人工摘要产能存在明显上限。

目标用户

  • 销售、HR顾问、研究人员、内容运营、知识库管理员

项目目标

  • 让用户在统一工作台内完成从大纲构建、素材引用到导出交付的闭环，提升创作速度与内容质量。

用户痛点

  • 研究报告和方案写作前期找资料、搭框架、组织逻辑耗时长。
  • 历史素材分散在文档、网页和团队知识中，难以在写作时稳定复用。
  • 长文写作容易出现上下文断裂、风格不统一和引用不可靠的问题。
  • 业务人员需要快速生成可交付内容，但又不能接受模型自由发挥产生幻觉。

使用场景

  • 销售根据客户行业、岗位和用工痛点，快速生成初步解决方案。
  • 研究人员导入PDF材料，自动生成报告大纲并分章节写作。
  • 团队将行业报告、政策文件和项目资料沉淀到素材库供RAG检索。
  • 市场同事将每周大量政策/竞对文章批量解读为凝练摘要，进入内部洞察推文或周报生产链路。
  • 内容运营结合产品卖点与热点，生成多风格对外宣传文案与公众号推文草稿，再人工定稿。
  • 内容编辑对已有段落进行扩写、缩写、总结、续写和全文风格优化。
产品方案与系统设计

产品方案

  • 构建首页入口、研究报告工作台、解决方案Agent和素材库四个模块，以“素材向量化 + 大纲控制 + 分步生成 + 人工确认”的方式提升内容生产效率。

为什么用 AI

  • 该场景依赖长文本组织、语义改写和知识检索，适合 Agent 分步写作与 RAG 强约束生成。

AI 的作用

  • 通过 Agent + RAG 完成大纲生成、分步写作、局部改写与全局优化

功能模块

  • 研究报告：AI生成大纲、文档导入、分步写作、局部改写、全文优化。
  • 素材库：公共素材、项目素材、链接解析、网络搜索和RAG向量化。
  • 解决方案：行业/岗位/痛点表单输入，四段式结构化方案生成。
  • 文本记忆：章节摘要沉淀，后续生成优先读取摘要以节省Token。
  • 导出与历史：Word导出、项目卡片、删除/导出/恢复等资产管理。

系统架构

  • 入口层：首页承载AI快速写作、研究报告、解决方案和历史项目管理。
  • 知识层：公共素材、项目素材、网络搜索结果统一清洗、分块、向量化。
  • Agent层：大纲Agent、写作Agent、摘要记忆Agent、提示词增强Agent。
  • 编辑层：富文本编辑器、局部改写、全文优化、双屏对比。
  • 交付层：自动保存、Word导出、历史项目恢复和文本记忆复用。

AI 与产品分工

  • AI：大纲生成、流式写作、段落改写、推荐追问与方案生成
  • 规则：四段式输出约束、字数限制、状态机流转、导出模板映射
  • 人工：核验关键内容、编辑章节、确认摘要记忆
  • 兜底：Token 超限/安全拦截/解析失败时提供可恢复提示和重试路径

Agent 分工

  • 大纲规划Agent：根据任务目标和素材上下文生成章节结构，并约束层级与格式边界。
  • 章节写作Agent：按大纲分步生成正文内容，支持流式产出与上下文连续性维护。
  • 素材检索Agent：连接RAG索引与网络检索结果，返回可引用证据并标记来源。
  • 全局优化Agent：对全文做风格统一、逻辑连贯性检查和可交付标准修正。

技术方案

  • RAG：对项目素材和网络搜索内容进行向量化召回，降低幻觉。
  • Function Call：集成搜索API和网页解析工具，获取外部资料。
  • Agent Workflow：将大纲、写作、摘要、提示词增强拆成独立能力节点。
  • 富文本编辑器：支持流式写作、局部改写、Accept/Retry/Discard状态。
  • Token控制：通过文本记忆和滑动窗口保留关键上下文。

个人职责与复盘

职责概述

  • 核心模块设计、写作状态机定义、RAG素材流与异常机制设计

个人工作

  • 设计首页、研究报告、解决方案和素材库的核心信息架构。
  • 定义AI写作状态机、局部改写交互和全文优化双屏对比流程。
  • 设计RAG素材流：上传、清洗、分块、向量化、召回与删除同步。
  • 沉淀Prompt策略和输出结构约束，确保业务方案格式稳定。

复盘

  • AI写作平台的核心不是让模型一次写完，而是把写作拆成可控步骤。
  • RAG素材必须有状态可见性，否则用户会误以为上传即可被模型引用。
  • 企业级写作要优先保证可靠性、引用依据和人工可编辑性。

经验与后续考虑

  • AI写作产品的核心不是“写得像人”，而是“可控、可追溯、可复用、可交付”。
