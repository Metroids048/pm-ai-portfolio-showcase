电商视频创作 Agent

电商运营提供商品素材和制作需求，即可开始策划短视频。制作完成后，运营可以单独修改字幕、配音或某个镜头。

我的职责

我设计从提交素材到交付可编辑视频工程的流程，明确策划、分镜、渲染各阶段的输出，以及局部修改和版本恢复规则。

交付与验证

用咖啡饮品样片验证生成、渲染、保存和局部编辑，并将创作、编辑、版本恢复和导出等功能封装为 OpenClaw 插件。

关键决策

开工前确认商品信息和成片规格

把需求、商品资料和输出规格写进工程，再确认商品事实、营销计划和时间线。关键素材或规格缺失时先补齐。

改单个对象时，先锁定对象和版本

区分首做、修改、重剪和生成变体。修改时绑定目标对象与当前版本，保留其余已确认内容。

按阶段保存，渲染失败可以恢复

按检查点执行制作。渲染后保存工程和视频版本；质量检查没通过时，保留上一有效版本和失败原因。

方案与验证

六类电商任务如何走同一工作台

围绕上新、详情、教程、系列、促销、问答六类场景，我设计统一输入、场景识别和差异化制作策略。商品事实、受众、卖点、画幅与时长先写入工作单，用户可以确认后再制作。

把创建、编辑、精剪及一稿多版放进同一工程。导出和恢复走精确指令，标题、字幕、转场与音量先定位可编辑对象；复杂创意由模型制定计划，缺商品事实或基准版本时先澄清。

从导演计划到可编辑工程

商品理解、营销计划、创意与导演时间线依次进入 AgentKernel，按 17 个生产阶段形成 NativeDocument。稳定场景和节点 ID 支持局部修改；HTML／GSAP 与 HyperFrames 完成动效编排、检查和严格渲染。

用 MiniMax TTS 接入中文配音、音色切换、字幕联动与背景音乐混音。导出 MP4 与可继续编辑的原生工程，版本不可覆盖，支持撤销、重做、局部恢复和重新导出。版本冲突明确提示，失败保留有效版本并从检查点继续。

样片验证与插件化交付

用咖啡饮品样片验证从素材到成片的流程，并测试单独修改视频对象。迁移到 OpenClaw 后，用户可以通过对话生成或编辑视频、检索资源、恢复版本和导出。

校验阶段检查结构、媒体与渲染，质量不足时有一次有界修复。配音节奏、开头吸引力及商业导演质量仍需逐案观片和听音。

项目全貌

原案例资料 · 电商视频创作 Agent

项目背景与范围

项目概述

  • 面向电商内容创作者的多模态视频 Agent，将商品素材和一句话需求转成可检查、可编辑、可恢复的视频工程，并支持在同一对话中持续修改和版本化交付。

业务场景

  • 上传商品图片或视频并描述目标，Agent 完成商品理解、营销策划、镜头编排、视频制作与持续修改

背景

  • 电商视频创作往往从零散图片、长视频和一句模糊需求开始。传统模板工具能快速拼接素材，却难以说明系统理解了什么商品、为何选择这些卖点、修改影响了哪些对象，也缺少失败恢复和版本证据。项目因此将一次性生成改造成可审计的 Agent 工作流：先理解商品事实和业务目标，再形成营销与导演计划，最终交付可继续编辑的视频工程。

目标用户

  • 电商运营、短视频编导、品牌内容团队、独立商家与需要快速验证创意的产品团队

项目目标

  • 让用户在一个工作台内完成“素材与目标输入 → Agent 理解与规划 → 视频生产 → 自然语言修改 → 版本化导出”，同时确保素材事实、修改范围、失败状态和交付版本都可追溯。

用户痛点

  • 输入往往只有一句话和混合素材，商品、受众、卖点、画幅与时长缺少统一结构。
  • 提示词直接生成视频属于黑盒，用户无法检查营销策略和镜头计划，也难以定位低质量原因。
  • 自然语言修改容易误伤未提及内容，字幕、声音、转场和素材之间缺少稳定对象边界。
  • 导出覆盖旧结果、页面刷新丢状态或失败后从头执行，会显著增加视频迭代成本。
  • 工程检查通过不等于商业成片好看，必须区分可渲染、媒体正确与营销表现。

使用场景

  • 上传商品图片或视频，选择单品上新、操作演示、商品详情、系列展示、活动促销或选购问答场景。
  • 输入一句话目标，由系统补齐画幅、时长、素材范围和需要澄清的信息。
  • 先检查 Agent 形成的工作单，再执行完整视频生产。
  • 用“价格更醒目”“第三幕切快一点”“只恢复上一版转场”等自然语言修改真实对象。
  • 在同一工程中查看不可覆盖的 revision，执行撤销、重做、指定版本恢复和重新导出。
  • 下载 MP4 与包含 NativeDocument、HTML/GSAP 和素材引用的原生工程包。
产品方案与系统设计

产品方案

  • 采用“语义规划 + 确定性执行”的双层方案。WebUI 将文字、附件和输出规格写入工程；Router 先处理精确控制与对象级编辑，复杂需求才进入受 Schema 约束的模型路由；AgentKernel 按检查点调用生产工具形成 ProductBrief、MarketingPlan、CreativeDirection、DirectorTimeline 和 NativeDocument；HyperFrames 负责工程检查与严格渲染；发布层生成不可覆盖版本，质量不足时只允许一次有界修复并保留上一有效结果。

为什么用 AI

  • 电商视频需求同时包含商品理解、受众判断、营销表达、镜头选择和视听编排，适合由模型处理语义和创意决策；但素材真实性、对象定位、版本冲突、预算、渲染和发布必须交给确定性系统约束。项目让 AI 负责理解与规划，让规则和工具负责执行与守门。

AI 的作用

  • 把自然语言需求转成可检查的商品事实、营销计划、导演时间线和可编辑视频工程

功能模块

  • 多模态创作工作台：素材上传、任务目标、业务场景、画幅、时长、先检查、生成与作品预览。
  • 需求与路由层：幂等、基准版本校验、最近对话、精确控制、对象级编辑、语义路由与最小澄清。
  • 业务规划层：ProductBrief、MarketingPlan、CreativeDirection、DirectorTimeline 与 HF Design Plan。
  • Agent 执行层：AgentKernel、ToolRegistry、阶段检查点、模型预算、失败恢复和调用回执。
  • 原生工程层：NativeDocument、稳定对象 ID、素材引用、字幕、音频、时间线和局部 patch。
  • 渲染与质量层：HTML/CSS/GSAP 编译、HyperFrames check/strict render、媒体审查与有界 revision。
  • 版本交付层：不可覆盖 revision、分支、撤销/重做、选择性恢复、MP4 与原生工程包。

系统架构

  • 体验层：电商视频工作台、创作对话、场景入口、播放器和版本控件。
  • 路由层：control → exact/local edit → semantic route → clarify。
  • 规划层：ProductBrief → MarketingPlan → CreativeDirection → DirectorTimeline。
  • 执行层：AgentKernel、ToolRegistry、checkpoint、预算与失败恢复。
  • 工程层：NativeDocument、object map、HTML/CSS/GSAP、音频图与资源引用。
  • 交付层：HyperFrames、媒体审查、revision、MP4、工程包和审计回执。

AI 与产品分工

  • AI 负责：复杂意图理解、商品理解、受众与卖点策划、创意方向、导演时间线和语义级修改。
  • 规则负责：消息幂等、版本冲突、素材归属、对象 ID、时长边界、预算、状态机和发布条件。
  • 工具负责：素材观察、音视频处理、字幕与声音、场景编译、HyperFrames 检查、渲染和打包。
  • 人工负责：确认关键素材与商业主张，连续观看和听音，判断前三秒吸引力、卖点表达与品牌适配。
  • 兜底机制：信息不足先澄清；模型或外部依赖失败保存 checkpoint；质量失败保留上一有效版本，不静默降级。

Agent 分工

  • L0 精确控制：导出、撤销、重做、恢复和状态查询不调用模型。
  • L1 对象级编辑：标题、字幕、音量、转场等修改先定位真实对象，再生成受控 patch。
  • L2 语义规划：复杂创意请求由模型输出目标、保持项和理由，再映射到工程操作。
  • L3 最小澄清：缺少基准版本、素材或业务信息会实质改变结果时，先提问而不是猜测。
  • 生产 Agent：按商品理解、营销策划、导演、资源、场景创作、组装和预览审查逐步执行。

技术方案

  • 原生 JavaScript WebUI + Node.js 服务：单一创作入口、工程消息持久化与异步任务状态。
  • 结构化模型调用：JSON Schema 约束 Router、ProductBrief、MarketingPlan 与 DirectorTimeline。
  • AgentKernel + ToolRegistry：17 个生产阶段按预算、幂等键和 checkpoint 执行。
  • NativeDocument v3：稳定场景/节点 ID、显式锚点、对象映射和局部失效计算。
  • HyperFrames 0.8.33 + GSAP：原生 HTML 视频工程、动效、检查和 strict render。
  • FFmpeg / FFprobe：媒体探测、裁切、音频处理、成片编码与输出核验。
需求、交付与验证

需求与验收规则

  • 创建、编辑、精剪和一稿多版必须进入同一工程与消息历史，不能产生脱离上下文的新链路。
  • 路由只选择模式与能力，不能直接写工程；真正执行必须经过 AgentKernel 和已注册工具。
  • 模型不得虚构价格、功效和商品事实，所有主张必须来自用户输入或可定位素材证据。
  • 每次修改绑定 baseRevisionId；页面过期时返回版本冲突，禁止静默覆盖新结果。
  • 发布前必须完成 NativeDocument 编译和 HyperFrames 检查；失败保留上一有效 revision。
  • 自动质量修复有明确次数边界，不能无限重跑，也不能把降级输出标记为通过。

业务价值

  • 把一次性视频生成升级为可检查、可继续编辑的工程工作流。
  • 用商品事实、营销计划和导演时间线把“为什么这样做”保留下来。
  • 自然语言修改绑定真实对象与版本，未提及内容进入 preserve 集合，降低误伤。
  • checkpoint、失败回执和不可覆盖 revision 让长链路可以恢复、审计和回滚。
  • MP4 与原生工程同时交付，用户得到的不只是一次性结果文件。
  • 明确区分工程闭环与商业质量，不以测试数量或成功渲染冒充营销效果。

原案例成果描述

  • 贯通素材输入、分阶段生产、HyperFrames 渲染、不可变版本与自然语言对象级修改；商业导演质量仍持续迭代

个人职责与复盘

职责概述

  • 独立负责产品定义、Agent 工作流、路由与状态设计、WebUI、质量边界和真实验收

个人工作

  • 定义从用户素材和模糊需求到可编辑视频工程的产品主链与完成标准。
  • 设计 create/edit/recut/variant 路由、澄清策略、版本冲突和失败恢复机制。
  • 拆解商品理解、营销策划、导演规划与确定性生产工具的职责边界。
  • 设计工作台信息架构，让输入、执行状态、作品预览、版本和下载保持在同一上下文。
  • 组织真实素材、浏览器、模型、媒体与成片验证，并保留失败和未验收边界。
  • 通过 AI coding agent 推进实现，自己负责产品判断、边界审计和交付收口。

复盘

  • 视频 Agent 的核心不是多套模板，而是让商品事实、营销策略和导演计划成为后续阶段共同消费的业务语义。
  • 模型适合做语义与创意判断，但对象、版本、预算、渲染和发布必须由确定性系统控制。
  • 工程检查通过只能证明可运行，不能替代完整观片、听音和真实营销效果判断。
  • 修改闭环必须同时保存 target、preserve 和 base revision，否则自然语言越灵活，误伤风险越高。
  • 当前工程生产闭环已经贯通，自然语言对象级修改较完整；营销导演质量、声音驱动节奏和全场景人工验收仍需继续提升。
