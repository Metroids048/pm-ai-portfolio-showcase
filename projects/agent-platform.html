企业级智能体服务平台

深圳优量科技有限公司 · 2026.05–2026.08

企业原有七类 AI 系统分别维护。这个平台为用户提供统一入口，让运营集中管理智能体的发布、权限和反馈。

我的职责

我盘点现有系统，划分四个功能域，明确运营与开发的分工，并设计权限、审核发布和反馈分派规则。

交付与验证

交付产品方案、PRD 和约 42 页静态原型，串起运营、开发、用户和专家四条使用流程。原型使用脱敏或模拟数据。

方案与验证

四域如何协作

盘点七类既有系统后，我划出用户、运营管理、基础服务和数据采集汇聚四个域。统一门户承载智能体中心、会话、收藏和个人资源；运营侧管理权限、资产摘要和状态，低代码 IDE、外部 IDE／Git、知识中心、训练与标注继续由对应执行平台维护。

通过 API 同步资产元数据、权限和状态，用单点登录跳转到详细操作页，以适配层处理协议转换和故障隔离。同步异常时仍可浏览运营页。统一埋点汇聚到数仓，关联调用、质量、资源和成本。

运营边界与资源复用

将低代码和代码智能体归入同一运营生命周期，统一草稿、审核中、已上架、已停用、已下架和已驳回状态。个人、组织与全公司范围走不同审核路径，非所有者可查看或复制草稿，第三方智能体保持外部维护。

模型、提示词、变量、Workflow、MCP、Skills 和知识库在开发平台配置。运营侧只读取摘要与版本。MCP 支持登记、调试和启停，Skills 支持长期绑定或会话临时使用，两者都检查权限及资源状态。

梳理从数据接入、格式与质量校验、清洗、标注、版本，到训练、评估和推理登记的路径；设计异构 GPU／节点、模型文件、API 密钥、调用量与 Token 成本的关联视图。

从反馈到新版本

把用户主动反馈和超时、空响应等系统异常归到关联对象、严重程度与负责人。领域知识问题进入专家工作台，可领取、校对、确认和归档，系统问题回到开发及运营。处理结果关联到智能体、知识、数据、模型或权限配置。

方案与原型覆盖 12 类能力，包含约 35 个管理页面和 7 个用户门户页面。演示用脱敏或模拟数据呈现运营、开发、用户和专家的操作流程。

智能体运营：列表、搜索筛选、创建/导入、第三方接入、来源识别、版本、审核、发布、上/下架、停止维护和归档。

智能体开发协同：低代码 IDE 与代码开发双入口，运营平台展示配置摘要，开发平台承载画像、模型、提示词、变量、工具、Workflow、MCP、Skills、知识库、调试和版本历史。

工具与提示词工程：MCP Server 注册、工具发现/在线调试/版本/启停，Skill 创建/导入/测试/发布，以及模板、变量、多模型对比和 A/B 测试。

知识中心：平台/组织/个人知识库视图、文档数量/存储量、解析/向量化/入库状态、授权、关联智能体和调用统计。

模型服务：基础模型、微调模型、视觉/语音/OCR/Embedding 模型登记，模型权限、推理端点、并发限制、配额、训练和评估入口。

数据治理：数据概览、数据集接入、样本预览、格式/Schema/质量校验、清洗、纯文本/图文标注、数据集版本和训练关联。

算力与部署：异构 GPU 厂商、节点、集群、模型部署、推理后端、模型文件、API 密钥、调用量、Token、资源消耗和成本分析。

反馈中心：系统采集与用户主动反馈、自动分类、严重程度、关联对象、处理状态、附件/日志、分派和处理记录。

专家工作台：任务大厅、积分/悬赏、智能推荐、领取、处理中/待确认/已完成状态、专家方案校对和创建者确认归档。

系统与授权：用户/组织/角色/菜单/按钮/API 管理，按公司/组织/个人分级授权智能体、知识库、数据集、模型、MCP 工具和功能。

报表与数据采集：统一埋点 SDK、数据管道、数仓和指标中心，汇总智能体、知识库、数据集、模型、资源和安全合规指标。

运营平台只维护业务状态、访问范围、审核发布和配置摘要；模型、提示词、工具、Workflow、知识库与 Skills 在开发平台维护。

一个智能体只有一个所有者；非所有者只读或复制草稿，第三方智能体不能进入开发平台修改。

访问范围统一为个人/组织/全公司，并决定直接上架或进入组织/平台审核路径。

智能体运营状态统一为草稿、审核中、已上架、已停用、已下架、已驳回；危险操作必须二次确认并记录原因。

只有已启用且有权限的 Skills 可长期绑定或会话临时使用；失效资源保留提示但不得注入运行。

低代码和代码智能体统一纳入版本、审核、上/下架、停止维护、归档和运行观察。

数据接入必须校验格式、Schema、完整性、准确性和一致性；训练任务引用明确的数据集与模型版本。

底层系统通过 API 同步元数据/状态，通过 SSO 进入重操作页面；同步失败不得阻断运营平台核心浏览与治理。

反馈必须记录关联对象、严重程度、状态、负责人和处理记录；领域知识问题进入专家工作台。

统一埋点不得阻塞业务主流程，报表指标必须定义计算口径、维度、时间范围和数据来源。

项目全貌

原案例资料 · 企业级智能体服务平台

项目背景与范围

项目概述

  • 面向 B 端组织的企业 AI 应用生产与治理平台，以运营控制面连接已有开发、知识、模型、数据、算力和认证系统，覆盖智能体编排、MCP/Skills、RAG、训练评估、资源计量、权限审核和反馈回流。

业务场景

  • 整合七类既有 AI 系统，建立智能体开发、模型/数据/知识/算力协同与全生命周期运营底座

背景

  • 企业已经具备底层知识库/算力/模型平台、智能体开发平台、知识中心、模型服务平台、数据治理平台、统一认证中心和企业智能办公助手七类系统，但各系统分散建设、各自维护入口。用户需要在多个系统间切换，运营侧看不到智能体、知识、模型、数据的全局状态，应用可以被做出来，却难以统一发布、训练、监控和持续优化。

目标用户

  • 企业业务用户、AI 应用开发者、算法/模型团队、平台运营、专家和系统管理员

项目目标

  • 以运营管理为中枢，建设覆盖用户、运营管理、基础服务、数据采集汇聚四个域的企业 AI 服务平台：统一资产视图、生命周期、权限和运营入口，同时通过 API 同步与 SSO 跳转复用已有开发、知识、模型、数据和认证能力。

用户痛点

  • 七类既有系统各自维护列表和状态，用户需要多次登录和跳转，运营没有统一的资产全景。
  • 运营平台与开发平台边界模糊，智能体画像、模型、提示词、工具、知识库和运行状态容易被重复维护。
  • 低代码编排智能体与代码开发智能体的创建、存储、版本和部署方式不同，却需要统一运营和发布治理。
  • MCP、Skills、Workflow、知识库等能力缺少可复用的资源摘要、版本和权限规则，容易重复集成或误用失效资源。
  • 数据采集、清洗、标注、数据集版本、训练任务和评估结果没有稳定回流到 Agent 开发与应用运营。
  • 模型服务、GPU/节点、部署、API 密钥、Token 用量和成本数据分散，资源与业务价值难以关联。
  • 用户反馈、系统异常和领域知识问题没有统一分类、分派、专家处理和回流闭环。
  • 企业场景需要组织、角色、菜单、接口、模型和资源的分级授权，并留下可审计的状态与操作记录。

使用场景

  • 平台运营从列表创建或接入智能体，查看来源、版本、访问范围、审核进度和运行摘要。
  • 低代码智能体跳转开发平台完成工作流、模型、知识库和 MCP/Skills 配置；代码智能体在外部 IDE/Git 开发后回到运营平台登记。
  • 开发者在三列编辑器中维护智能体画像、模型参数、提示词、变量、工具、Workflow、MCP、Skills 和知识库，并在线预览调试。
  • 工具维护者注册 MCP Server、在线调试工具、管理版本和启停；Skill 作为方法型指令资源被长期绑定或在会话中临时选择。
  • 知识管理员统一查看平台级/组织级/个人级知识库、文档处理状态、关联智能体和使用统计，创建与文档管理通过 SSO 跳转。
  • 算法与数据团队完成数据接入、格式/Schema/质量校验、清洗、标注、数据集版本、训练任务、评估和模型登记。
  • 资源管理员纳管异构 GPU、节点、集群、模型部署、推理后端、模型文件、API 密钥及 Token/调用量成本。
  • 业务用户从统一门户使用已上架智能体，提交主动反馈；系统同时采集异常、超时、空响应等运行反馈。
  • 运营按反馈类型、关联对象、严重程度和状态分派问题；领域知识类问题进入专家工作台，系统/功能类问题回到开发与运营。
  • 管理者从智能体、知识库、数据集、模型和资源报表查看调用量、活跃度、质量、成本和组织分布。
产品方案与系统设计

产品方案

  • 采用“用户域 + 运营管理域 + 基础服务域 + 数据采集汇聚层”的四域架构，并把运营平台定义为控制面：负责智能体资产、访问范围、审核发布、运行观察、反馈分派、专家协同和治理报表；已有开发、知识、模型、数据、算力与认证平台作为能力执行面，通过 API 同步元数据/状态、SSO 跳转重操作页面、适配层完成协议转换与故障隔离；统一埋点与数据管道把使用、质量、资源和成本汇聚到报表中心。

为什么用 AI

  • 平台本身不是单一模型能力，而是把 Agent、Workflow、MCP、Skills、RAG、提示词工程、数据清洗/标注、模型训练评估、异构算力、智能编码和组织权限组合成可复用的 AI 应用生产与治理能力；AI 负责理解、检索、调用和生成，规则与人工负责状态、权限、审核和高风险兜底。

AI 的作用

  • 把 Agent、Workflow、MCP、Skills、RAG、模型、数据和算力编排成可开发、可训练、可发布、可运营的企业能力

功能模块

  • 用户客户端：统一认证、智能体中心、对话、个人知识库/数据集/模型、收藏、历史会话和反馈入口。
  • 智能体运营：列表、搜索筛选、创建/导入、第三方接入、来源识别、版本、审核、发布、上/下架、停止维护和归档。
  • 智能体开发协同：低代码 IDE 与代码开发双入口，运营平台展示配置摘要，开发平台承载画像、模型、提示词、变量、工具、Workflow、MCP、Skills、知识库、调试和版本历史。
  • 工具与提示词工程：MCP Server 注册、工具发现/在线调试/版本/启停，Skill 创建/导入/测试/发布，以及模板、变量、多模型对比和 A/B 测试。
  • 知识中心：平台/组织/个人知识库视图、文档数量/存储量、解析/向量化/入库状态、授权、关联智能体和调用统计。
  • 模型服务：基础模型、微调模型、视觉/语音/OCR/Embedding 模型登记，模型权限、推理端点、并发限制、配额、训练和评估入口。
  • 数据治理：数据概览、数据集接入、样本预览、格式/Schema/质量校验、清洗、纯文本/图文标注、数据集版本和训练关联。
  • 算力与部署：异构 GPU 厂商、节点、集群、模型部署、推理后端、模型文件、API 密钥、调用量、Token、资源消耗和成本分析。
  • 反馈中心：系统采集与用户主动反馈、自动分类、严重程度、关联对象、处理状态、附件/日志、分派和处理记录。
  • 专家工作台：任务大厅、积分/悬赏、智能推荐、领取、处理中/待确认/已完成状态、专家方案校对和创建者确认归档。
  • 系统与授权：用户/组织/角色/菜单/按钮/API 管理，按公司/组织/个人分级授权智能体、知识库、数据集、模型、MCP 工具和功能。
  • 报表与数据采集：统一埋点 SDK、数据管道、数仓和指标中心，汇总智能体、知识库、数据集、模型、资源和安全合规指标。

系统架构

  • 用户域：统一登录、智能体中心、对话、个人空间、会话历史、收藏和反馈入口。
  • 运营管理域：智能体、工具摘要、提示词资产、知识/模型/数据视图、反馈、专家、授权、系统和报表。
  • 开发/运行执行面：低代码编排器、代码开发协同、模型、工具、Workflow、MCP、Skills、知识和运行时。
  • 知识/模型/数据基础服务：知识库管理、数据治理、训练评估、模型服务登记和资产状态同步。
  • 资源服务层：异构 GPU、节点、集群、模型部署、推理后端、模型文件、API 密钥和计量。
  • 子系统适配层：统一协议转换、元数据聚合、状态同步、权限同步和故障隔离。
  • 数据采集汇聚层：统一埋点、消息/数据管道、数仓、指标计算和报表输出。
  • 治理与安全横切层：统一认证、组织、角色、菜单、按钮、API、资源访问、审计与告警。

AI 与产品分工

  • AI：任务理解、问答生成、摘要抽取、检索增强、工具调用、Workflow 编排、代码辅助和反馈分类。
  • 知识增强：文档解析、Embedding、召回、重排和引用，让回答能回到可核验的知识片段。
  • 数据/模型：数据清洗、标注、增强、训练、评估和版本登记，把数据资产转成可复用模型能力。
  • 规则：生命周期状态、访问范围、审核节点、版本回退、资源权限、配额、审计和异常状态机。
  • 人工：运营审核发布与下架，专家复核领域反馈，开发者确认版本、提示词、知识和训练策略。
  • 基础设施：模型推理、知识服务、异构 GPU、部署、密钥、SSO、埋点和计量由基础服务层承载。
  • 兜底：底层平台不可用、资源失效、权限不足、低置信回答和反馈无法自动归因时，进入可追踪的待处理队列。

Agent 分工

  • 应用编排 Agent：围绕业务目标组合模型、提示词、知识、工具、Workflow、MCP 和 Skills，并保留版本与依赖摘要。
  • 知识问答 Agent：执行查询改写、召回、重排、引用和无证据拒答，把回答与知识来源关联。
  • 数据/模型工作流：把数据校验、清洗、标注、训练、评估、模型登记和发布组织成可追踪任务。
  • 运营治理 Agent：辅助识别资源失效、权限异常、运行风险和审核材料缺口，但不代替运营人员做最终发布决策。
  • 反馈分诊 Agent：识别反馈类型、严重程度和关联对象，推荐处理团队；不确定时进入人工分派。
  • 专家协同 Agent：根据领域、任务难度和历史质量推荐专家，支持领取、校对、确认与知识回流。
  • 智能编码助手：为平台开发者提供代码生成、理解、调试和工程协作支持，并受项目规则、测试和权限约束。

技术方案

  • 控制面/执行面分层：运营平台维护业务状态、访问范围、审核发布和运行观察；开发/运行平台维护具体能力配置与运行时。
  • 四域架构：用户域、运营管理域、基础服务域、数据采集汇聚层，各域有明确入口和责任边界。
  • 集成模式：API 同步智能体/知识库/模型/数据元数据与状态，SSO 跳转低代码 IDE、文档管理、训练和标注页面。
  • 子系统适配层：做协议转换、数据聚合、状态同步和故障隔离，避免已有平台差异扩散到运营主链路。
  • Agent 资产组合：画像、模型、提示词、变量、Tools、Workflow、MCP、Skills、知识库和版本历史可追踪引用。
  • 数据与模型链路：格式/Schema/质量校验、清洗、标注、数据集版本、训练空跑/正式任务、评估与模型回流。
  • 资源与计量链路：GPU/节点/集群、模型部署、推理后端、模型文件、API 密钥、Token/调用量和成本看板。
  • 统一数据采集：埋点 SDK → 数据管道 → 数仓 → 报表/指标，支持业务、质量、资源和安全合规分析。
  • 静态原型：约 35 个根页面 + 7 个用户门户页面，用脱敏/mock 数据演示运营、开发、用户和专家主路径。
需求、交付与验证

需求与验收规则

  • 运营平台只维护业务状态、访问范围、审核发布和配置摘要；模型、提示词、工具、Workflow、知识库与 Skills 在开发平台维护。
  • 一个智能体只有一个所有者；非所有者只读或复制草稿，第三方智能体不能进入开发平台修改。
  • 访问范围统一为个人/组织/全公司，并决定直接上架或进入组织/平台审核路径。
  • 智能体运营状态统一为草稿、审核中、已上架、已停用、已下架、已驳回；危险操作必须二次确认并记录原因。
  • 只有已启用且有权限的 Skills 可长期绑定或会话临时使用；失效资源保留提示但不得注入运行。
  • 低代码和代码智能体统一纳入版本、审核、上/下架、停止维护、归档和运行观察。
  • 数据接入必须校验格式、Schema、完整性、准确性和一致性；训练任务引用明确的数据集与模型版本。
  • 底层系统通过 API 同步元数据/状态，通过 SSO 进入重操作页面；同步失败不得阻断运营平台核心浏览与治理。
  • 反馈必须记录关联对象、严重程度、状态、负责人和处理记录；领域知识问题进入专家工作台。
  • 统一埋点不得阻塞业务主流程，报表指标必须定义计算口径、维度、时间范围和数据来源。

业务价值

  • 把七类分散系统收敛为统一用户入口和运营控制面，降低业务用户与运营人员跨系统切换成本。
  • 用四域架构和控制面/执行面边界明确每类资产、状态和动作的唯一责任方，减少重复维护与状态漂移。
  • 把低代码与代码智能体纳入同一生命周期，统一来源识别、访问范围、审核、上/下架、版本和运行观察。
  • 把模型、数据、知识、MCP/Skills、Workflow、算力和密钥转成可授权、可引用、可统计的企业 AI 资产。
  • 把系统异常和用户反馈连接到运营、开发者与专家工作台，形成“发现 → 分派 → 处理 → 确认 → 回流”的闭环。
  • 用统一埋点与报表口径关联调用量、质量、资源和成本，为后续容量规划和价值评估建立数据基础。
  • 公开材料只陈述已完成的方案、PRD、原型和演示路径，不把 mock 看板、待确认接口或未联调能力包装成生产成果。

个人职责与复盘

职责概述

  • 独立负责系统盘点、四域架构、控制面/执行面边界、生命周期、权限、PRD、原型和 AI agent 协同落地

个人工作

  • 盘点七类既有系统与业务角色，梳理智能体、知识库、模型、数据集、工具和算力的跨平台关系。
  • 定义四域总体架构和运营控制面/开发执行面边界，明确状态、配置摘要、跳转入口和唯一事实源。
  • 设计低代码/代码智能体统一生命周期、六态运营模型、访问范围、审核路径、版本更新和下架治理。
  • 拆解用户门户、运营平台、开发协同、模型/数据/知识/算力、反馈专家、授权报表等模块并输出 PRD/原型。
  • 把 AI、规则、人工和基础设施分工写进产品链路，补齐权限、审计、异常与人工复核。
  • 让 AI coding agent 执行原型与文档实现，自己负责需求取舍、边界审计、公开证据和验收收口。

复盘

  • 大型 ToB AI 平台的核心不是堆菜单，而是为用户、资产、权限、状态和指标建立共同语义。
  • 运营平台应回答“能否上架、谁能使用、运行如何”，开发平台应回答“如何工作、引用什么能力”，二者不能互相越权。
  • 已有系统不适合全部重建，API 同步 + SSO 跳转 + 适配层更适合渐进式整合，但必须定义同步失败和数据新鲜度。
  • Skills 不是工具调用或知识检索，而是方法型指令资源；长期绑定与会话临时使用要分开，避免污染默认配置。
  • 反馈闭环的关键不是收集数量，而是能否关联对象、明确责任人、保留处理记录并回流到知识/模型/数据/应用。
  • 方案、PRD、静态原型、mock 和真实生产联调必须分层表达，平台规模越大越不能用页面数量代替业务效果。
